# ADR-0003: --apply フラグによるドライラン既定方式

## Status
Accepted (2026-09-07)

## Context
`bump`コマンドは実ファイルをリネームする破壊的操作になりうる。
誤ったファイル名を指定した場合や、意図しないタイミングでの実行により、
アーティストの作業ファイルを意図せず変更してしまうリスクがある。

## Decision
`bump`コマンドは既定でドライラン（結果の提示のみ）とし、
実際のファイルシステム変更には明示的な `--apply` フラグを要求する。
同様の考え方を`init`コマンドの「既存フォルダは上書きしない」設計にも適用する。

## Consequences
良い: 誤操作によるデータ破壊を防止できる（fail-safeな既定動作）
悪い: スクリプトから自動実行する場合、毎回`--apply`を明示する必要がありやや冗長

## Alternatives Considered
- 既定で即実行し、`--dry-run`フラグで確認モードに切り替える方式:
  一般的なUnixツールの慣習（`rsync`等）に近いが、
  「破壊的操作は明示的なオプトインを要求する」という安全側の設計思想を優先し却下した。
