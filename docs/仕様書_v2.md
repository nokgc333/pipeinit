## 4. data-design

### 4.1 ルールファイルスキーマ（ver2: schema_version・applies_to追加）

```yaml
# rules/game.yaml
schema_version: 1
project_type: game
version_format: "v{n:03d}"
folder_template:
  - path: "assets/characters"
    required: true
  - path: "assets/environments"
    required: true
  - path: "shots"
    required: true
naming_patterns:
  - pattern: '^SHOT\d{3}_[a-z]+_v\d{3}\.\w+$'
    description: "ショットファイル命名規則（例: SHOT010_lighting_v003.hip）"
    applies_to: shot
  - pattern: '^[A-Z][A-Za-z0-9_]*\.(fbx|abc|usd)$'
    description: "アセットファイル命名規則"
    applies_to: asset
```

### 4.2 データ辞書（ver2版、applies_to追加）

| キー | 型 | 必須 | 既定値 | 説明 |
|---|---|---|---|---|
| `schema_version` | int | ◯（v2で必須化） | - | スキーマの破壊的変更を検知するためのバージョン番号 |
| `project_type` | string | ◯ | - | ルールファイルの識別子 |
| `version_format` | string | ◯ | `v{n:03d}` | バージョン番号のフォーマット文字列 |
| `folder_template[].path` | string | ◯ | - | 生成する相対パス（SEC-002検証対象） |
| `folder_template[].required` | bool | - | true | falseの場合、存在しなくても警告に留める |
| `naming_patterns[].pattern` | string(regex) | ◯ | - | Pythonの`re`モジュール互換の正規表現 |
| `naming_patterns[].description` | string | ◯ | - | 違反時にユーザーへ表示する説明文 |
| `naming_patterns[].applies_to` | enum(shot/asset/all) | - | all | ファイル種別ごとの規則分離（ver2新設） |

### 4.3 バリデーション実装（YAMLスキーマチェック、ver2新規コード）

```python
# pipeinit/rules.py（抜粋）
from __future__ import annotations

from pathlib import Path
from typing import Any

import yaml

REQUIRED_KEYS = {"schema_version", "project_type", "folder_template", "naming_patterns"}


class RuleFileError(Exception):
    """ルールYAMLの読込・検証エラー（exit code 2 = E001に対応）。"""


def load_rule_file(path: Path) -> dict[str, Any]:
    try:
        raw = yaml.safe_load(path.read_text(encoding="utf-8"))  # SEC-001
    except yaml.YAMLError as exc:
        raise RuleFileError(f"{path} contains invalid YAML: {exc}") from exc

    if not isinstance(raw, dict):
        raise RuleFileError(f"{path} must be a YAML mapping at the top level")

    missing = REQUIRED_KEYS - raw.keys()
    if missing:
        raise RuleFileError(
            f"{path} is missing required key(s): {', '.join(sorted(missing))}"
        )
    return raw
```

# pipeinit/cli.py（抜粋）
from __future__ import annotations

import sys
from pathlib import Path

import click

from pipeinit.rules import RuleFileError, load_rule_file
from pipeinit.templates import PathTraversalError, generate_tree
from pipeinit.validator import validate_directory


@click.group()
@click.version_option()
def main() -> None:
    """PipeInit: CG/ゲームパイプライン向けフォルダ構造・命名規則自動化CLI。"""


@main.command()
@click.option("--type", "project_type", required=True,
              type=click.Choice(["game", "film", "generic"]))
@click.option("--path", "target_path", default=".", type=click.Path())
def init(project_type: str, target_path: str) -> None:
    """プロジェクト種別に応じたフォルダツリーを生成する（FR-001）。"""
    base = Path(target_path)
    if not base.exists() or not os_access_writable(base):
        click.echo(f"Error: '{base}' is not writable", err=True)
        sys.exit(5)  # E005
    try:
        rule = load_rule_file(Path(__file__).parent.parent / "rules" / f"{project_type}.yaml")
        created, skipped = generate_tree(rule, base)
    except RuleFileError as exc:
        click.echo(f"Error: {exc}", err=True)
        sys.exit(1)  # E001
    except PathTraversalError as exc:
        click.echo(f"Error: {exc}", err=True)
        sys.exit(6)  # E006
    click.echo(f"Created {len(created)} folders, skipped {len(skipped)} (already exist)")

@click.argument("path", type=click.Path(exists=True))
@click.option("--rules", "rules_path", default=None, type=click.Path())

## 8. business-logic（アルゴリズム全文、ver2深掘り）

### 8.1 バージョン番号インクリメント（実装コード）

```python
# pipeinit/validator.py（抜粋）
import re


VERSION_RE = re.compile(r"^(?P<stem>.+_v)(?P<num>\d+)(?P<ext>\.\w+)$")


def bump_version(filename: str) -> str:
    """ファイル名末尾のバージョン番号を1つ繰り上げる。

    v999 -> v1000 のような桁上げは、ゼロ埋めせず桁数を拡張する。
    バージョン部が見つからない場合は ValueError を送出する（E004に対応）。
    """
    match = VERSION_RE.match(filename)
    if match is None:
        raise ValueError(f"'{filename}' does not match any known version pattern")

    stem, num_str, ext = match.group("stem", "num", "ext")
    width = len(num_str)
    next_num = int(num_str) + 1
    next_str = str(next_num).zfill(width) if len(str(next_num)) <= width else str(next_num)
    return f"{stem}{next_str}{ext}"
```

### 8.2 端数処理・特殊ケース（v1から変更なし）

| ケース | 挙動 |
|---|---|
| バージョン部が存在しない | `ValueError` → CLI層でE004に変換 |
| バージョン部が複数マッチ | 正規表現`^(?P<stem>.+_v)`の貪欲マッチにより最後の`_v\d+`が優先される（末尾優先） |
| 既に採用済みの次バージョンファイルが存在 | `--apply`時にE007で拒否（要件定義書TC-016） |

### 8.3 パス正規化・パストラバーサル検証（実装コード、ver2新規）

```python
# pipeinit/templates.py（抜粋）
from pathlib import Path


class PathTraversalError(Exception):
    """生成先パスがベースディレクトリの外側を指している場合に送出（E006）。"""


def resolve_safe_path(base: Path, relative: str) -> Path:
    resolved = (base / relative).resolve()
    base_resolved = base.resolve()
    if not resolved.is_relative_to(base_resolved):
        raise PathTraversalError(
            f"folder_template path '{relative}' escapes the target directory"
        )
    return resolved
```

### 14.4 ADR-0003（ver2新規、全文）

```markdown
# ADR-0003: --apply フラグによるドライラン既定方式

## Status
Accepted (2026-09-07)

## Context
`bump`コマンドは実ファイルをリネームする破壊的操作になりうる。
誤ったファイル名を指定した場合や、意図しないタイミングでの実行により、
アーティストの作業ファイルを意図せず変更してしまうリスクがある（脅威モデル§12.2 Tampering参照）。

## Decision
`bump`コマンドは既定でドライラン（結果の提示のみ）とし、
実際のファイルシステム変更には明示的な `--apply` フラグを要求する。
同様の考え方を`init`コマンドの「既存フォルダは上書きしない」設計にも適用する。

## Consequences
良い: 誤操作によるデータ破壊を防止できる（fail-safeな既定動作）
悪い: スクリプトから自動実行する場合、毎回`--apply`を明示する必要がありやや冗長

## Alternatives Considered
- 既定で即実行し、`--dry-run`フラグで確認モードに切り替える方式:
  一般的なUnixツールの慣習（`rsync`等）に近いが、
  「破壊的操作は明示的なオプトインを要求する」という安全側の設計思想を優先し却下した。
```
